## PAGE DETAILS

### 1. Understand Me

- Work experience, internships and projects (add multiple entries: title, org, description)
- Technical skills (free text tags + suggestions)
- Human/transferable skills
- Free-text "describe what you can do in your own words" (used for semantic matching, e.g. "I make charts and reports")
- Career interests and goals

Step B: "Career Profile Summary" page:
- Template-generated professional overview (no LLM required).
- Clearly separate "Skills you stated" from "Inferred transferable strengths (system inference)".
- Preliminary career directions and areas for development.
- Disclaimer: "This reflects information you submitted plus labelled system inferences. It is not a psychological or competence assessment."

Step C: "Your market, linked to you": a section on the same flow showing 3-5 market insights relevant to the user's field and skills (reuse trend data, filtered by profile), each with a source and date, and a CTA to Explore Me.

### 2. Explore Me (nested)
- **Career Market:** the Future Role Matcher. Ranked career recommendations, each card showing a "prototype suitability indicator" (NOT a guarantee), matched skills (green), missing skills (amber) and a plain-language "Why this career?" explanation. Add a compare-two-careers view and a "Choose this career" button that sets the target career for the Roadmap.
- **Trends:** the Career Evolution Radar. Cards or a timeline of AI/workforce trends, each with title, summary, affected occupations/skills, SOURCE NAME + URL and PUBLICATION/UPDATE DATE. Load from an editable JSON/DB file (data/trends.json) so it is "maintainable" and not hard-coded in the UI. Show a "Last updated" label. Include filters by industry/skill.
- **Career Time Machine:** a signature interactive feature. Pick a career, then toggle between Scenario A "Gradual AI Transformation" and Scenario B "Rapid AI Transformation". Show how skill priorities shift (skills that rise, hold or decline in priority, with animated bars or a radar chart) and the recommended preparation actions for each scenario. Always show the label: "Illustrative planning scenarios, not forecasts of job loss." Scenarios come from explicit assumptions in data/scenarios.json.

### 3. Roadmap (nested)
- **Skill Roadmap:** for the chosen career, show the skill gaps and an ORDERED learning pathway. Each step has: skill, why it matters, learning activity, estimated duration (label "provider-stated" or "estimated"), and 1-3 resource links (free or affordable courses such as Coursera, edX, freeCodeCamp, Google, Khan Academy, with a source label). Use real, well-known course URLs only; if unsure of a URL, link to the provider's search page instead of inventing a link. Each step has a "Mark as complete" checkbox.
- **Progress Tracker:** overall progress ring, per-skill status (Not started / In progress / Completed), completion dates, optional notes or evidence link (e.g., a GitHub project), and a "skills gained so far" list. Persist progress (database or localStorage).
- **My Resume:** a formal, ATS-friendly resume generator. It is built from the profile PLUS completed roadmap skills (completed skills are added to the Skills section; completed courses go under "Certifications & Learning" with the provider named). The target career sets the professional summary wording. Sections: Contact (editable placeholders), Professional Summary, Education, Experience/Projects, Skills (grouped: Technical / Professional), Certifications & Learning. Provide a live preview, an editable text for each section, 2 clean templates, and "Download PDF" and "Print". Do NOT fabricate experience or employers: only use data the user entered or completed. Add a note: "Review and edit before sending to employers."

### 4. Impact
- **SDG Impact:** an interactive Career → Skills → SDGs relationship visualisation (a node-link or Sankey-style diagram). It shows (a) occupation-level mappings and (b) skill-level mappings, focused on the user's COMPLETED roadmap skills ("your SDG record"). Each link has a short justification, e.g. "Data analysis can support SDG 13 when applied to climate/environmental monitoring". Selective mappings only (not every SDG for every job). Show an SDG badge grid with the user's SDGs highlighted and a counter ("Your skills contribute to 4 SDGs"). Disclaimer: "Potential contributions, not measured impact."

## MATCHING ENGINE (important architecture)
- Create a small curated dataset (data/occupations.json) of about 10-12 occupations (e.g., Data Analyst, Data Scientist, Software Developer, AI/ML Engineer, Business Analyst, UX Designer, Digital Marketing Specialist, Cybersecurity Analyst, Project Manager, Cloud Engineer, Education Technologist) with required skills (loosely ESCO-style), importance weights, SDG tags, and scenario shift data. Also create data/skills.json, data/courses.json and data/sdg_mappings.json.
- Build a **SkillMatcher interface** with two implementations:
  1. `deterministic` (default fallback): normalised keyword/synonym/token-overlap matching.
  2. `embedding`: calls an external HTTP inference endpoint (configured with env vars EMBEDDING_API_URL and EMBEDDING_API_KEY; I will connect a RunPod endpoint running sentence-transformers/all-MiniLM-L6-v2 later). The request/response format should be simple JSON: send a list of texts, receive a list of vectors. The cosine similarity is computed in the backend.
- Auto-fallback: if the env vars are missing or the call fails or times out, silently use `deterministic` and show a small status badge in the UI: "Matching mode: AI semantic (RunPod)" or "Matching mode: Rule-based fallback".
- Final score = combination of semantic/keyword similarity + structured rules (required-skill coverage, interest alignment). Always return the explanation (matched skills, missing skills, reasons).
- Add a /api/health endpoint and a small "AI status" page or panel that shows which mode is active and a live test box ("creating charts and reports" → top similar skills with similarity scores). I will use it as technical evidence in my pitch.
